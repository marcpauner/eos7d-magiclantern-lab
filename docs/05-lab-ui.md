# 5. Lab UI: a redesigned menu for the 7D

`labui.mo` replaces what the Trash button shows with a redesigned menu:
**Ajustes** (categories), **Superposiciones** (overlays) and **Zebras**,
with anti-aliased type, LED-style indicators, an inverted focus row and
graduated rulers. Anything not redesigned yet opens in the classic menu.
Design: `ui-design/` mockups (Space Grotesk + JetBrains Mono, neutrals and
one lime accent).

## How it runs on the camera

* **Taking the screen.** Trash still opens Magic Lantern's menu, which hides
  Canon's GUI. The module then sets `menu_redraw_blocked` (as the Arkanoid
  module does) so ML stops drawing, and draws its own screens.
* **Buttons.** Module key handlers run before ML's menu handler
  (`handle_module_keys` comes before `handle_ml_menu_erase` /
  `handle_ml_menu_keys` in `src/gui-common.c`), so keys reach the module
  first. They are queued and handled in the module's own task.
* **Settings.** ML's menu entries, read and written with
  `menu_get_value_from_script` / `menu_set_value_from_script`, the API Lua
  uses. Submenus are menus named after their parent entry, so
  `("Zebras", "Overexposure")` works. None of the entries used here has a
  custom `.select`, so values are set directly.
* **Classic menu.** Q, or a category that is not redesigned, leaves ML's own
  menu on screen (`select_menu_by_name`, then `menu_redraw`). *Prefs > Lab
  UI* turns the module's takeover off.

## Display facts this relies on

| Fact | Source |
|---|---|
| ML draws a 720x480 bitmap on a 4:3 (640x480) LCD: x is scaled 9/8 | `platform/7D.203/internals.h` |
| 8-bit indexed bitmap, pitch 960; idle buffer + `bmp_idle_copy` avoids flicker | `src/bmp.h`, `src/bmp.c` |
| Palette entries are set with `EngDrvOut(LCD_Palette[3*i])` (and `+0x300`) | `alter_bitmap_palette_entry`, `src/tweaks.c` |
| Hardware palette format `0xOOYYUUVV`; from RGB: Y = 0.9216 x BT.601 luma, U x 0.79, V x 1.11 (clamped) | fitted to the 16 RGB / hardware pairs in `src/disp_direct.c`, within 1 unit for the 8 colours |

While the screens are up the module borrows 43 palette entries from `0xA0`
and puts Canon's values back when it leaves.

## Code

| File | What |
|---|---|
| `ui/src/lab_gfx.c` | shapes in eighths of a pixel with 4x4 anti-aliasing, 4-bit glyphs, RGB565 bands of 48 rows, RGB555 -> palette table |
| `ui/src/lab_ui.c` | screens, layout (display pixels from the mockups), navigation, settings mapping |
| `ui/src/lab_assets.c` | generated by `ui/tools/gen_assets.py`: 13 font sizes, 11 icons, palette (fonts: SIL OFL, `ui/fonts/`) |
| `ui/module/labui/labui.c` | camera glue: keys, screen takeover, palette, settings backend |

Freestanding C99, no floating point. Loaded size about 348 KB (14 KB code,
112 KB glyphs, 100 KB buffers).

## Tests

* `ui/sim/run.sh` builds the same code for the PC with AddressSanitizer and
  UBSan, runs 18 behaviour checks against a fake settings store that keeps
  ML's ranges, and renders every screen to PNG (`ui/sim/out/*_lcd.png` is the
  4:3 view).
* `ui/build.sh` builds `labui.mo` in the ML tree and checks every symbol it
  needs against the official `7D_203.sym`.

QEMU cannot show the 7D GUI (see [03](03-qemu.md)), so the camera is the
first place the module really runs.

## Status

Built and simulated. Not yet run on the camera: the palette format was
fitted from the bootloader palette and has to be confirmed there, and the
redraw speed is unmeasured.
